# Bootstrap CSS Retirement and 2026 Polish

Date: 2026-08-22
Status: Approved

## Problem

Bootstrap is gone as a dependency, but `ui/styles/` still carries 1,315 lines of
hand-written Bootstrap-named component CSS (`.btn`, `.modal`, `.form-control`,
`.dropdown`, `.toast`, `.navbar`, `.card`, `.table`), a legacy alias block in the
`@theme` tokens, and provably dead selectors. DESIGN.md's own Phase 2 backlog
lists this debt. Visuals must get no worse at any step, and a small curated set
of changes should move the surface closer to a 2026 look.

## Scope decisions (user-approved)

1. **Shared primitives:** extract `app-button.vue` and `alert-message.vue`
   components. `.table`, `.form-*`, `.card` stay as slim Tailwind v4
   `@layer components` classes. No other components.
2. **Visual polish:** small curated list only — thin spinner arc, badge weight,
   collapse card/table border treatments 3 → 2, normalize the 5 label-gesture
   variants. One re-baseline PR. Everything else stays pixel-identical.

## Current state (evidence)

- `ui/styles/` total: 1,315 lines across `theme.css` (107), `base.css` (161),
  `components.css` barrel (9) and 8 partials: buttons (205), forms (189),
  controls (161), feedback (143), modals (85), navigation (83), surfaces (63),
  mobile-cards (58), motion (51).
- **Dead selectors (verified by grep against all templates and runtime class
  bindings):** `.dropdown`, `.dropdown-menu`, `.dropdown-menu.show`,
  `.dropdown-item` in `navigation.css` (~45 lines); `.toast:not(.show)` in
  `feedback.css` (`toast-container.vue` hardcodes `class="toast show"`).
- **Live but misleading:** `.dropdown-toggle::after` caret is consumed by
  `filter-toggle.vue`. `.fade-slide-*` classes are generated by Vue
  `<transition name="fade-slide">` in `app.vue`. Both stay.
- **Stale E2E masking the dead code:**
  `TransactionManagementE2E.should display quick dates dropdown` still clicks a
  `.platform-btn` labelled "Quick Dates" and asserts `.dropdown-menu` becomes
  visible. The UI replaced that popup with a native
  `<select data-testid="quickDatesToggle">` (`transactions-view.vue`). The test
  reports green only because `RetryExtension` implements
  `TestExecutionExceptionHandler` and returns without rethrowing for the first
  3 matching failures — in JUnit that marks the test **passed** and never
  re-runs it. Every `@Retry` E2E test can silently rot this way.
- **Legacy `@theme` aliases still referenced:** `--color-signal-indigo(-deep)`
  16 refs / 11 files, `--color-gray-100..900` ramp 81 refs,
  `--color-ink-muted` 14, `--color-control-graphite(-deep)` 8,
  `--color-status-*` 8, `--color-body-secondary` 1.
- **Tokens are also consumed as generated Tailwind utilities**, which no
  `var()` grep finds: `text-body-secondary` ×10, `text-gray-600` ×13,
  `text-signal-indigo` ×2, `bg-gray-100` ×1. Deleting a `@theme` key stops
  generating its utility class, so those sites lose their colour silently.
  Every token deletion must sweep `var()` refs **and** utility-class refs.
  `--color-body-secondary` has zero `var()` refs but 10 utility refs — live,
  not dead.
- **Four gray shades have no Statement equivalent:** gray-200
  `oklch(0.93 0.008 85)`, gray-500 `oklch(0.55 0.014 60)`, gray-700
  `oklch(0.4 0.014 60)`, gray-800 `oklch(0.32 0.013 60)`. The other five map
  exactly (100→surface-hover, 300→hairline, 400→hairline-strong,
  600→ink-soft, 900→ink).
- **16 neutral black tints** in three syntaxes (`rgb(0 0 0 / α)`,
  `rgba(0, 0, 0, α)`, `rgb(0_0_0/0.075)`). These are pure black, while every
  Statement shadow/hairline token is ink-hue (`oklch(0.24 0.012 60 / α)`) —
  so swapping them onto existing tokens is a visual change, not a rename.
- **Pixel gate:** 40 baselines in `docs/superpowers/baseline/`, 3 viewports,
  6 stubbed routes, 7 modals, `maxDiffPixels: 0` — but per-pixel `threshold`
  is the Playwright default 0.2, so the gate is blind to close colours.
  `palette.spec` walks AA contrast and focus rings.
- **Test-selector coupling:** Selenide E2E and Vitest tests select by Bootstrap
  class names. Class names must survive as DOM hooks.

## Design

Five phases, each its own GitHub issue + `feature/<issue>-<desc>` branch + PR
(`Closes #XXX`). Order: A → B → D → C → E. Four phases are zero-visual-delta
and verified byte-identical against the existing baselines; only Phase E
changes pixels and re-baselines, once.

### Phase A — Fix the retry bug, then the CSS it was hiding (zero delta)

- **Fix `RetryExtension` first.** Replace the `TestExecutionExceptionHandler`
  with an `InvocationInterceptor` that actually re-invokes the test method.
  All 4 E2E classes (29 tests) opt in with
  `onExceptions = [ElementNotFound, TimeoutException]`, so every
  missing-element assertion in the suite has been swallowed. Cover it with a
  fast unit test that runs in the normal `./gradlew test` task.
- **Triage what the fix reveals.** Running the E2E suite with retry working
  may surface further rotted tests beyond quick-dates. Fix what it finds;
  report anything too large to absorb rather than widening silently.
- Rewrite `should display quick dates dropdown` to assert the real control:
  `[data-testid="quickDatesToggle"]` visible, more than one `<option>`, and
  selecting an option fills `#fromDate`.
- Delete `.dropdown`, `.dropdown-menu(.show)`, `.dropdown-item` from
  `navigation.css`; delete `.toast:not(.show)` from `feedback.css`.
- Verify: visual suite green against committed baselines; `npm test`;
  E2E green via `npm run test:e2e`.

### Phase B — Relocate single-consumer CSS into components (zero delta)

- `modals.css` → `modal-shell.vue` scoped style (sole consumer; all `.modal-*`
  elements live in its own template; the `autofocus` attribute on
  `.modal-content` is load-bearing and stays).
- Navbar rules (`.navbar`, `.navbar-nav`, `.nav-link`) → `nav-bar.vue`.
- `.dropdown-toggle::after` caret → `filter-toggle.vue`.
- Toast rules → `toast-container.vue`.
- Move the global `:focus-visible` rule from `buttons.css` to `base.css`.
- Scoped styles inject unlayered and beat `@layer`; identical rules at higher
  precedence produce identical computed styles.
- Verify: byte-identical baselines including all 7 modal shots; `npm test`.

### Phase D — Extract app-button.vue and alert-message.vue (zero delta)

- `app-button.vue` renders the existing class names
  (`btn`, `btn-primary`, `btn-ghost`, `btn-add-new`) with spinner and disabled
  boilerplate; `alert-message.vue` renders `alert alert-<type>` with the
  dismiss button. Class names stay in the DOM so every existing E2E and unit
  selector keeps working — zero test churn.
- Replace all template usages. Button/alert CSS moves into the component file
  only when grep proves zero raw usages remain; `.btn-close` stays global
  (used raw in modal, toast and alert markup).
- Verify: byte-identical baselines; `npm test`; `npm run lint-format`;
  `npm run check-unused` clean.

### Phase C — Retire legacy tokens, tokenize black tints (zero delta, colour-only risk)

- Swap every reference — `var()` **and** generated utility class — for
  `--color-signal-indigo(-deep)`, `--color-control-graphite(-deep)`,
  `--color-status-*`, `--color-ink-muted`, `--color-body-secondary` and the
  `--color-gray-*` ramp onto the Statement token with the identical computed
  value, then delete the aliases from `@theme`.
- The four orphan gray shades keep their exact values under lightness-named
  tokens (`--color-hairline-soft`, `--color-ink-32/40/55`), flagged in
  DESIGN.md as consolidation candidates for a later pass.
- Black tints: deduplicate only where the same value repeats
  (`rgb(0 0 0 / 0.02)` ×3 → `--color-surface-tint`; the duplicated
  `0 0.125rem 0.25rem rgb(0 0 0 / 0.075)` card shadow ×2 → `--shadow-panel`)
  and modernize the two `rgba(0, 0, 0, α)` sites to space syntax. The
  remaining 9 one-off tints stay pure black and are recorded as open debt —
  moving them to the ink hue is a visual change and is not on the curated
  polish list.
- Runs after B and D so edits land in the files' final homes.
- Verify: the default gate cannot see close colours, so run a `threshold: 0`
  copy of the Playwright config twice — stashed vs applied — and byte-compare
  the actuals; `palette.spec` AA walker green.

### Phase E — Curated 2026 polish, one re-baseline (intentional delta)

- `.spinner-border`: thick 0.25em border → 2px thin arc.
- `.badge`: font-weight 700 → 550.
- Collapse the 3 card/table border treatments to 2 by standardizing on the
  hairline token pair (`hairline` for interior rules, `hairline-strong` for
  outer edges), retiring the odd-one-out `rgb(0 0 0 / 0.05)` card border.
- Normalize the 5 label-gesture variants to the canonical
  uppercase / 0.75rem / 600 / 0.05em gesture.
- Process: `impeccable` audit before and after; chrome-devtools MCP for live
  iteration; one commit re-baselining all 40 baselines; palette gate green.
- Update DESIGN.md: mark the Phase 2 backlog done, refresh the debt census.

## Cross-cutting rules

- Every PR that moves lines cited by DESIGN.md refreshes those `file:line`
  citations in the same PR.
- Repo conventions: no code comments, imperative ≤50-char commit subjects, no
  prefixes, no AI attribution, PRs reference their issue.
- `controls.css`, `motion.css`, skeleton styles and the modern
  `base-select` block in `forms.css` are Statement-native and out of scope.

## Non-goals

- No Tailwind utility rewrites of `.table` / `.form-*` / `.card` internals.
- No new visual ideas beyond the curated list.
- No renaming of DOM-hook class names.
- No move of the 9 one-off black tints onto the ink hue.
- No consolidation of the four orphan gray tones (values preserved, renamed).

## Risks

- **Colour-blind gate (Phase C):** mitigated by the threshold-0 double-run.
- **Utility-class blindness (Phase C):** a deleted `@theme` key silently stops
  generating its utility; mitigated by sweeping utility refs alongside `var()`
  refs and by a grep gate asserting zero surviving references per token.
- **Unknown E2E rot (Phase A):** a working retry may reveal more broken tests
  than the quick-dates one. Triage and report; do not widen scope silently.
- **Scoped-style precedence (Phase B):** moved rules win over `@layer` rules;
  safe only because the moves are whole-block and byte-verified.
- **Raw class stragglers (Phase D):** grep gate before moving CSS into the
  component; `.btn-close` explicitly kept global.
- **Baseline decay:** all routes are stubbed, so byte-identical comparison is
  meaningful; any red on an untouched phase means environment drift, not the
  change.
